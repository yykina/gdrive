rclone · Personal application by yykina

Privacy policy

Personal Google Drive access from the owner's computer.

Effective date: October 17, 2026. This policy describes yykina's personal OAuth application and local rclone setup described on the application home page.

Data accessed and its purpose

With the account owner's authorization, rclone accesses Google Drive file and folder metadata, including names, identifiers, sizes, timestamps, and directory relationships, as well as file contents. It uses this data to display folders and carry out file operations requested through the mounted filesystem.

Read and write permissions allow listing, downloading, uploading, editing, renaming, moving, and deleting files. Access is used for the owner's personal file management, not advertising, profiling, model training, or sale of data.

Storage and retention

OAuth access and refresh tokens are saved in the owner's local rclone configuration. Read and write caches are saved on that computer. Local logs may contain file names and operation metadata. Google Drive retains the cloud files under the owner's account and Google's own policies.

Cached files can remain on the computer until cache cleanup or removal by the owner; open files and pending uploads may be retained longer. Files moved to the desktop's local trash can remain there until the owner removes them. Cloud trash is separate from local trash.

Transfers and third parties

rclone communicates with Google's authorization and Drive services to authenticate and transfer files. This personal setup does not operate a separate server that receives Drive data, and it does not sell Drive data or transfer it to advertising, analytics, or AI training services.

This public information website is hosted by GitHub Pages. It has no sign-in form, OAuth callback, analytics scripts, or application cookies. Drive files and OAuth credentials are not published here. GitHub may process website request information under the GitHub Privacy Statement.

Security and control

Google API connections use HTTPS. Local credentials and caches rely on the owner's computer and filesystem protections; this setup does not add a separate encryption layer to cached files. The owner controls the computer, OAuth grant, and Google Drive account.

The owner can revoke this application's access in Google Account connections. Revocation prevents subsequent authorized requests but does not automatically remove downloaded files, local caches, logs, trash, or cloud files. Those copies can be removed separately by the owner.

Policy updates and contact

Updates to this setup's data practices will be reflected on this page. Questions can be directed to yykina through the project's issue tracker. Please do not include credentials or private file contents in public issues.
